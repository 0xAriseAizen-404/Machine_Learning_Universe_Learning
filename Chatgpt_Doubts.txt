# Part 1 — Data collection & EDA (corrected, expanded, practical)

## 1) Where data comes from — quick checklist

You’re right: Kaggle, UCI, GitHub, APIs, company DBs, web-scraping are common sources. Additions and cautions:

* **APIs / DBs / Streams**: respect rate limits and privacy; pull stable snapshots for experiments (don’t train on a live-changing stream unless that’s your goal).
* **Large data**: use chunked reads, Dask or PySpark if memory becomes an issue.
* **Provenance / versioning**: save raw copies (or use DVC) so you can reproduce results.

Common ingest functions (pandas): `read_csv`, `read_excel`, `read_json`, `read_html`, `read_sql`, plus `requests`/`pd.json_normalize` for APIs.

---

## 2) First EDA commands (the basics you already listed — use them in this order)

1. `df.shape`, `df.head()`, `df.dtypes`, `df.info()` — quick health check.
2. `df.describe()` — numeric summary (mean, std, min, quartiles).
3. `df.nunique()` — categorical cardinality.
4. `df.isnull().sum()` — missingness counts.
5. `df.value_counts()` for categorical features.
6. Plotting: histograms, boxplots (outliers), scatter (pairs), correlation heatmap, and for many features use pairplot / scatter matrix **but only on a sampled subset** if dataset is large.

**Rule:** do quick visuals early — they expose bad data, weird distributions, and duplicated rows fast.

---

## 3) Missing values — types & how to choose a strategy

First, know the missingness mechanism:

* **MCAR (Missing Completely At Random)** — safe to drop rows sometimes.
* **MAR (Missing At Random)** — missingness depends on observed data; imputation methods need to be careful.
* **MNAR (Missing Not At Random)** — missingness depends on the missing value itself (harder; needs domain thinking).

**When to drop vs impute**

* **Drop rows** if missing proportion is tiny (rule-of-thumb: < 1–5%) and MCAR.
* **Drop column** if > ~30–50% missing (depends on importance and cost to impute).
* **Impute** if the feature is important or missingness is non-trivial.

**Imputation choices — when to use which**

* **Mean**: use for roughly symmetric, normally distributed numeric features without big outliers.
* **Median**: use for skewed numeric features or when outliers exist (median is robust).
* **Mode**: use for categorical features (most common category).
* **Forward/Backfill**: use for time series where previous/next value is a reasonable proxy (e.g., sensor readings).
* **KNN imputer / Iterative (MICE)**: multivariate methods that use other features — better than simple imputation when relationships exist.
* **Model-based imputation**: train a model to predict missing values (use cross-validation to avoid leakage).
* **Missing indicator**: sometimes add a binary column `col_missing` to mark missingness — missing itself can be informative.

**Pitfall:** mean imputation reduces variance and can bias estimates — be cautious for downstream inference.

---

## 4) Outliers — detect & handle

* Detect with boxplots, z-score (>3) or IQR rule (outside [Q1−1.5*IQR, Q3+1.5*IQR]).
* Options: keep (if real), clip, transform (log), or remove (if clearly erroneous).
* Trees tolerate outliers; linear models and distance-based methods do not.

---

## 5) Correlation & covariance — what they mean

* **Covariance**: raw joint variability (scale-dependent).
* **Correlation (Pearson)**: normalized covariance (−1..1), shows linear relationship strength. Use `df.corr()` for a quick matrix.
* **Caveat**: correlation ≠ causation. Check for multicollinearity (very high correlation between features) — this can destabilize linear models (consider dropping or using regularization).

---

## 6) Categorical → Numeric: corrections to your notes

You listed one-hot, ordinal, label encoding. small corrections:

* **One-hot encoding**: creates binary columns (good for nominal categories with low cardinality). For linear models you may want to `drop_first=True` to avoid perfect multicollinearity (dummy variable trap).
* **Ordinal encoding**: use **only** when categories have a known, meaningful order (e.g., `['low','medium','high']`). Use `OrdinalEncoder` with the explicit ordering set.
* **Label encoding**: assigns integer labels (0,1,2...). **Do not** use this blindly for nominal features in linear models — it *introduces an artificial order*. `LabelEncoder` is appropriate for the target `y` in many cases, or for tree models sometimes, but be cautious.
* **Important correction**: label encoding does **not** use a decision tree to decide order. It simply maps categories to integers.
* **High-cardinality categories**: use target encoding (careful with leakage), hashing trick, or categorical embeddings (for neural nets).

---

## 7) Scaling — clear-up and when to use

You were close but a small clarification on **normalization**:

* **Standardization (StandardScaler)**: subtract mean, divide by std → resulting feature has mean ≈ 0 and std ≈ 1. Good for algorithms assuming Gaussian-like inputs (linear/logistic regression, SVM, PCA). Formula: ( z = \frac{x-\mu}{\sigma}).
* **Min–Max Scaling (MinMaxScaler)**: scales to ([0,1]) (or any range). Formula: (x'=\frac{x-\min}{\max-\min}). Useful for algorithms that need bounded inputs (neural nets with sigmoids), or when you want to preserve the shape of the distribution.
* **RobustScaler**: uses median and IQR — good when outliers exist.
* **Normalization (vector norm)**: typically means scaling each sample to unit norm (e.g., L2 norm = 1). This is different from min-max; used for text vectors or when you care about direction not magnitude.
* **Rule:** trees (RandomForest, XGBoost) generally don’t require scaling; distance-based and gradient-based methods often do (kNN, SVM, KMeans, neural nets).

**Always** `fit` scalers on the **training set** and `transform` validation/test sets with that same scaler (you already had this right).

---

## 8) Imbalanced classes — brief, practical advice

* **Simple checks**: look at class ratios.
* **Options**:

  * **Resampling**: oversample minority (SMOTE — synthetic samples), undersample majority, or hybrid.
  * **Algorithmic**: use `class_weight='balanced'` in many sklearn models (SVM, logistic, tree variants).
  * **Evaluation**: prefer precision/recall, F1, PR-AUC instead of accuracy.
  * **Advanced**: ensemble methods tuned for imbalance (balanced random forest), cost-sensitive learning, or focal loss for deep nets.

**Caveat:** SMOTE can create unrealistic synthetic examples if feature space is weird — visualize and validate.

---

## 9) Data leakage — the silent killer

Never fit transformers or impute using the whole dataset before splitting. Examples of leakage:

* Scaling or imputation fit on full dataset.
* Using future information (e.g., using target-derived features that include future values for time-series).
* Target encoding without proper CV smoothing (it leaks target into features).

Always use pipelines (`sklearn.pipeline.Pipeline`) and `ColumnTransformer` so preprocessing is bound to train folds automatically.

---

## Quick EDA checklist you can paste into notes

1. `df.info(), df.describe(), df.head()`
2. Missingness check `df.isnull().sum()` + `missingno.matrix` (if you want visuals)
3. Value counts for categoricals; `nunique()` for cardinals
4. Histograms & boxplots for distribution/outliers
5. Correlation heatmap for numeric features; check multicollinearity
6. For time-series: check stationarity, seasonality, missing timestamps
7. Baseline: simple model (mean predictor for regression, majority class for classification) to establish baseline.

# Part 2 — Feature Engineering & Preprocessing

## 1) Encoding Categorical Features (deeper clarity)

You listed **one-hot, ordinal, label encoding**. Let’s refine:

### One-Hot Encoding (OHE)

* **Use when:** categories have no natural order (color, city, country).
* Produces new binary columns (`red=1/0`, `blue=1/0`, etc.).
* **Pro tip:** if cardinality > ~20 unique values, OHE may blow up the feature space → better to use target encoding, hashing, or embeddings.
* **Drop-first**: for linear regression you might set `drop_first=True` to avoid the “dummy variable trap” (perfect collinearity).

### Ordinal Encoding

* **Use when:** categories have meaningful order (education level: “High School” < “Bachelor’s” < “Master’s”).
* You define the order explicitly in `OrdinalEncoder(categories=[['low','medium','high']])`.

### Label Encoding

* **Use for:** target `y` (classification labels).
* If used on features, only safe when the algorithm **does not assume order or distance** in inputs (e.g., tree-based models like DecisionTree, RandomForest, XGBoost).
* **Correction to your note:** it does **not** use decision trees internally. It’s just a simple integer map (`{‘cat’:0, ‘dog’:1, ‘fish’:2}`).

### Target / Mean Encoding

* Replace category with average target value.
* Useful for high-cardinality (e.g., 500 zip codes).
* **Warning:** leakage risk. Must do within CV folds, never on full dataset.

---

## 2) Scaling & Normalization (with “when to use what”)

You mostly nailed it, but here’s the clarified rulebook:

* **StandardScaler** (mean=0, std=1) → good default for linear/logistic regression, SVM, PCA, neural nets.
* **MinMaxScaler** (0–1 range) → useful when algorithm expects bounded values (e.g., sigmoid/tanh activations).
* **RobustScaler** → use when heavy outliers exist (scales with median & IQR).
* **Normalizer (vector norm)** → scales *rows* (not columns!) so each row has unit length. Useful for cosine similarity, text vectors, kNN.

**Algorithms that need scaling:**

* kNN, SVM, kMeans, PCA, gradient descent–based models.
  **Algorithms that don’t care much:**
* Decision trees, RandomForest, Gradient Boosted Trees (XGBoost, LightGBM, CatBoost).

---

## 3) Pipelines — avoid data leakage

Instead of manually fitting scalers/encoders, bind everything into a pipeline so train/test split is respected automatically.

Example pipeline for mixed data:

```python
from sklearn.pipeline import Pipeline
from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.impute import SimpleImputer
from sklearn.linear_model import LogisticRegression

# numeric + categorical columns
numeric_features = ['age', 'income']
categorical_features = ['city', 'gender']

# define transformers
numeric_transformer = Pipeline(steps=[
    ('imputer', SimpleImputer(strategy='median')),   # handle NaN
    ('scaler', StandardScaler())                     # scale
])

categorical_transformer = Pipeline(steps=[
    ('imputer', SimpleImputer(strategy='most_frequent')),  # fill NaN
    ('onehot', OneHotEncoder(handle_unknown='ignore'))     # encode
])

# combine into preprocessor
preprocessor = ColumnTransformer(
    transformers=[
        ('num', numeric_transformer, numeric_features),
        ('cat', categorical_transformer, categorical_features)
    ])

# full pipeline
clf = Pipeline(steps=[
    ('preprocessor', preprocessor),
    ('model', LogisticRegression())
])

clf.fit(X_train, y_train)
```

Benefits:

* Prevents leakage (only fits on train).
* Keeps preprocessing + model bound together → easy to save/deploy.
* Works smoothly with GridSearchCV.

---

## 4) Handling High Cardinality Categories

When categorical variables have **hundreds/thousands of unique values** (like `user_id`, `zipcode`, `product_id`):

* **HashingEncoder**: reduces space by hashing into a fixed number of bins.
* **Target Encoding**: encode category by mean target (careful: leakage).
* **Embeddings**: neural nets can learn dense representations for categories (e.g., `word2vec`-style).

---

## 5) Feature Creation (Feature Engineering)

Classic tricks:

* **Polynomial Features**: create interactions (x1 * x2, x1²). Good for linear models to capture non-linearity.
* **Binning**: convert continuous → categorical bins (`age` → `young/mid/old`). Helps tree models.
* **Log/Power transforms**: reduce skewness in heavy-tailed distributions.
* **Date-time features**: extract year, month, weekday, hour, season.
* **Domain-specific ratios**: e.g., `debt-to-income`, `price-per-square-foot`.

---

## 6) Imbalanced Classes — Practical Handling

Quick recap with code:

```python
from imblearn.over_sampling import SMOTE
sm = SMOTE()
X_res, y_res = sm.fit_resample(X_train, y_train)
```

But remember:

* Try `class_weight='balanced'` before jumping to SMOTE.
* Evaluate with F1, ROC-AUC, PR-AUC (not accuracy).
* Sometimes imbalance is natural (fraud detection = 1% positive). Better to tolerate imbalance than force fake balance.

---

## 7) Quick Rules You Can Paste Into Notes

* Use **pipelines** to prevent leakage.
* **Encode** categoricals with OHE (low-cardinality) or Ordinal (ordered). Avoid LabelEncoder except for target or tree models.
* **Scale** if using distance- or gradient-based algorithms.
* Don’t scale for trees.
* Handle imbalance with `class_weight` or resampling (SMOTE, undersampling).
* Check high-cardinality → use hashing or target encoding.
* Always keep raw, immutable copy of dataset.
